# TOPAS 3000A — C++ AsyncAPI Client

Runnable scenario snippets for consuming TOPAS 3000A AMQP 1.0
messages from modern C++ (C++17), using the Apache Qpid Proton C++
client and `nlohmann/json` for JSON parsing.

## Layout

- `sdk/` — **not present yet**: a typed C++ SDK is deferred to a
  follow-up sub-project. Each snippet parses incoming JSON
  with `nlohmann::json`; once the SDK ships, swap the
  `nlohmann::json` access for `j.get<MyStruct>()` into the generated
  struct.
- `snippets/s1.cpp` — subscribe to `detector.measurement` and print messages.
- `snippets/s2.cpp` — subscribe to `*.fault` (all faults across all domains; A8).
- `snippets/s3.cpp` — publish a VMS DisplayMessage and await the correlated response (A4 + A6).
- `snippets/s4.cpp` — distinguish sync vs delta messages and detect sync-batch completion (A3 + A5).
- `snippets/s5.cpp` — subscribe to `traffic-signal.measurement` (DATEX-II 2017 profile).
- `snippets/s6.cpp` — subscribe to `transport-link.measurement` and dispatch on the SCOOT/GPS/ANPR `kind` discriminator (F6).
- `snippets/s7.cpp` — consume the static network topology across `network.{node,link,zone,path,turn}` and build an in-memory `std::map`.

## Setup

The snippets need two dependencies:

- **Qpid Proton C++** (the AMQP 1.0 client) — Debian/Ubuntu package
  `libqpid-proton-cpp12-dev`; Fedora `qpid-proton-cpp-devel`; vcpkg
  `qpid-proton`.
- **nlohmann/json** (header-only JSON library) — Debian/Ubuntu
  `nlohmann-json3-dev`; Fedora `json-devel`; vcpkg `nlohmann-json`.

A minimal `CMakeLists.txt` co-located with this `snippets/` directory:

```cmake
cmake_minimum_required(VERSION 3.16)
project(topas_asyncapi_snippets CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(Proton REQUIRED COMPONENTS Cpp)
find_package(nlohmann_json REQUIRED)

foreach(s s1 s2 s3 s4 s5 s6 s7)
    add_executable(${s} snippets/${s}.cpp)
    target_link_libraries(${s} PRIVATE Proton::cpp nlohmann_json::nlohmann_json)
endforeach()
```

> Some Debian/Ubuntu versions ship the CMake config under the
> `ProtonCpp` name instead of the `Proton` `Cpp` component; if
> `find_package(Proton ...)` fails, try
> `find_package(ProtonCpp REQUIRED)` and link `Proton::cpp` (or
> `ProtonCpp::cpp` depending on the package's exported targets).

### Build

```bash
cmake -B build
cmake --build build
```

If you are using vcpkg, prepend the toolchain file:

```bash
cmake -B build -DCMAKE_TOOLCHAIN_FILE=/path/to/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build
```

## Run

Set `TOPAS_AMQP_URL` to your broker (defaults to
`amqps://localhost:5671`). For local development against an Apache
ActiveMQ Artemis broker:

```bash
export TOPAS_AMQP_URL=amqps://localhost:5671

./build/s1
./build/s5
```

### Environment variables

| Variable | Default | Used by |
| --- | --- | --- |
| `TOPAS_AMQP_URL` | `amqps://localhost:5671` | all snippets |
| `TOPAS_MAX_MESSAGES` | `5` (S4 uses `20`) | S1, S2, S4, S5, S6 |
| `TOPAS_ORIGINATOR` | `asyncapi-clients-s3-demo` | S3 (sets `x-originator` per A4) |

The names match the Python, Java, and C# snippets' env vars so the
docs stay consistent across languages.

### mTLS

The defaults assume `amqps://` — Qpid Proton C++ negotiates TLS
through the URL scheme. To present a client certificate (mTLS), pass
`proton::ssl_client_options` via `proton::connection_options::ssl_client_options(...)`
and feed the container with those options from
`on_container_start`. The exact API is shown in the Qpid Proton C++
examples that ship with the library (`ssl_client.cpp`).

## Don't hand-edit

The contents of `snippets/` are generated by
`asyncapi_clients/generator/generate.py`. Re-run with
`make asyncapi-clients` after changing `asyncapi.yaml` or any
template under `asyncapi_clients/templates/cpp/`.
